# wiki-lint 設計ノート

> SKILL.md=「何をするか（指示）」/ 本ファイル=「なぜこの形か（意図・解釈・却下案・守る失敗）」。実行時は非読込。更新時に改訂する。SKILL.md は再掲せず参照に留める。
>
> プラグイン横断の判断（未解決リンクの位置づけ・description と index の一元化・運用ドキュメントの扱い）は [../../RATIONALE.md](../../RATIONALE.md) を参照。

## 目的と背景

運用で徐々にたまる不健全さ（矛盾・stale・孤立・規約違反）の検出器。検出と修正を分離し、修正は人間 / wiki-ingest / wiki-schema に委ねる。

## 中核的な設計判断

### 【load-bearing】検出のみ、自動修正しない
- **決定**: リンク削除・矛盾の片寄せ・ページ削除を lint 単独で実行しない。レポートと log を残すのみ。
- **防いでいる失敗**: 誤検出に基づく自動修正で正しい知識を壊すこと。矛盾の解消は原典確認（人間の領分）が要る。
- **出所**: 初期設計（v0.1）

### 【load-bearing】既知の矛盾と新規の矛盾を分けて報告
- **決定**: 検出前に log.md の `**Query**` / `**Ingest**` エントリから既知の矛盾を抽出し、レポートで「既知の未解決」と「新規発見」を区別する。
- **防いでいる失敗**: 毎回同じ矛盾をゼロから再報告して優先度判定が狂い、「累積している問題」が見えなくなること。
- **出所**: 初期設計（v0.1）

### 未解決リンクは typo / 作成候補に仕分けて報告
- **決定**: リンク先不在をエラー一覧ではなく仕分けリストとして出す。類似ファイル名があれば typo、複数ページから参照され欠落概念（4.4）と一致すれば作成候補と推定する。
- **防いでいる失敗**: OKF §5.3 が有効と定める「未執筆知識のリンク」を機械的に断罪し、TODO マーカーとしての価値を潰すこと（詳細はプラグイン RATIONALE 参照）。
- **出所**: OKF SPEC §5.3 の精読（2026-07-24）

### 除外規則の簡素化（wikilink ヒューリスティックの廃止）
- **決定**: チェック対象外は「コードフェンス内・スキーマファイル・log.md・外部 URL」の4種のみ。
- **却下した代替案**: 旧仕様のプレースホルダ判定（`[[ページ名]]` 等の説明文パターンを除外する曖昧なヒューリスティック）— wikilink 廃止で相対リンクの解決が機械的になり、不要になった。
- **出所**: OKF 刷新（2026-07-24）。wikilink を再導入するとこの複雑さが戻る点に注意
