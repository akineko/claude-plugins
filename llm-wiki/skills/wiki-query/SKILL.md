# Wiki への問い合わせ（query）

Wiki を一次情報源として扱い、関連ページから回答を組み立てる。**回答が新しい横断的知見を含むなら、Wiki に topic ページとして書き戻す**ことで、次回以降の検索コストが下がり知識が累積する。

## 基本原則

- **index.md から始める**: 全ページを総当りせず、まずカタログを読む。これが Wiki の価値の半分
- **ソースまで遡る**: 回答の根拠は `[[source-*]]` まで遡って引用する。中間の `[[concept-*]]` ページだけで答えない
- **確信度を示す**: 「Wiki 内で見つけた」 / 「Wiki にはないので一般知識から答えた」 / 「Wiki に矛盾がある」を明確に区別する
- **書き戻しを忘れない**: 価値ある回答（新しい統合・横断的知見）は新規 `topic-*.md` として保存。これがないと Wiki は累積しない

## ワークフロー

```
入力（質問）
  │
  ├─ Phase 1: Wiki ルートとスキーマの確定
  ├─ Phase 2: index.md から候補ページを特定
  ├─ Phase 3: 候補ページを精読
  ├─ Phase 4: 回答の組み立て
  ├─ Phase 5: 回答提示と書き戻し判断
  └─ Phase 6: 書き戻し（必要時のみ）と log 記録
```

## Phase 1: Wiki ルートとスキーマの確定

`$ARGUMENTS` から Wiki ルートを判定。指定がなければ `./wiki/` → `./` の順で `CLAUDE.md` または `AGENTS.md` を探索する。見つからなければ「Wiki が見つからない」と伝えて中止。

スキーマを読み、ページタイプの命名規約を把握する（Phase 6 の書き戻し時に使う）。

## Phase 2: index.md から候補ページを特定

`<wiki-root>/index.md` を `Read` し、質問のキーワード・概念に **意味的に** マッチするページを 5〜15 個ピックアップする。

- 完全一致だけでなく、関連する概念・人物・周辺トピックも候補にする
- カテゴリ見出しを参考に「この質問はどのカテゴリに属するか」を判断
- 候補が 3 個未満なら、`Glob` または `Grep` で全ページのファイル名・タイトルを補助的に検索する

```bash
# 補助的なフォールバック検索
grep -l "<キーワード>" <wiki-root>/*.md
```

候補が 0 件の場合は Phase 4 で「Wiki にはこの話題のページが無い」を明示する。

## Phase 3: 候補ページを精読

特定したページを `Read` する。読み取りの観点:

- **直接的な回答**: 質問にそのまま答える記述があるか
- **根拠ソース**: 主張の出典 `[[source-*]]` が示されているか
- **関連ページへのリンク**: `[[...]]` で指定されている先も追加候補になる
- **矛盾**: 同じ事実について複数のページで異なる記述があるか

必要に応じて、リンク先のページを 1〜2 ホップ追跡する。深く追いすぎると発散するので最大 2 ホップに制限する。

## Phase 4: 回答の組み立て

以下の構造で回答を組み立てる:

```markdown
## 回答

{1〜3 段落の本文。Wiki 内のページから引用するときは [[ページ名]] を本文中に埋め込む}

## 根拠

- [[source-foo]]: {要点1}
- [[source-bar]]: {要点2}
- [[concept-baz]]: {定義の参照}

## 確信度と前提

- Wiki 内で **見つけた** 部分: {本文の N 段落目までの記述}
- Wiki に **無い** 部分: {一般知識で補った場合の該当箇所。明示する}
- 矛盾の検出: {あれば内容、なければこの項目自体を省略}
```

ルール:

- 一般知識で補った場合は **必ず明示**する。Wiki の記述と混ぜない
- 矛盾を発見したら回答内で言及する。**勝手に片方を採用しない**（lint で扱う事項）
- 質問が曖昧なら、回答前に AskUserQuestion で絞り込む

### 4.1 確信度セクションの項目省略

「Wiki に無い部分」「矛盾の検出」が **該当なし** の場合は、その項目自体を省略してよい（「なし」と書く必要はない）。すべての項目が省略されるなら、確信度セクション自体を省略する（暗黙的に「Wiki 内で完結している」と読める）。

冗長な「なし」を並べると読み手の負荷が上がるので、省略を優先する。

## Phase 5: 回答提示と書き戻し判断

回答を提示した後、以下を判定する:

| 判定 | 例 | 書き戻すか |
|---|---|---|
| 既存ページにそのまま書いてあった | `[[concept-foo]]` の本文をほぼ転記しただけ | 書き戻さない |
| 既存ページの組み合わせで構成された **新しい統合** | 3 つの source を統合した結論や、横断的なテーマ整理 | **書き戻す** |
| 一般知識で補った要素を含む | Wiki に無い部分が回答の核を占める | 書き戻さない（Wiki の純度が下がる）。代わりに「`wiki-ingest` でソース取り込みを推奨」を伝える |
| 矛盾を発見した | 既存ページ間で異なる記述 | 書き戻さない（lint 対象として log に記録） |

書き戻し判定が「書き戻す」の場合、ユーザーに確認:

```
この回答は Wiki に新しい知見を加えています。
新規ページ topic-{提案 slug}.md として書き戻しますか？

- ファイル名候補: topic-{slug}.md
- カバーする内容: {1 行サマリ}
- 関連ページ: [[...]] {3〜5 個}

書き戻しますか？
1. はい（提案された名前で書き戻す）
2. 名前を変えて書き戻す
3. 書き戻さない
```

## Phase 6: 書き戻し（必要時のみ）と log 記録

### 6.1 topic ページの作成

書き戻しが合意されたら `<wiki-root>/topic-{slug}.md` を作成:

```markdown
---
title: {ページの正式な題名}
type: topic
created: {今日の日付}
updated: {今日の日付}
aliases: []
tags: []
---

# {題名}

{回答本文を Wiki ページの体裁に整形した内容}

## 根拠

- [[source-foo]]
- [[source-bar]]

## 関連

- [[concept-baz]]
- [[topic-...]]
```

### 6.2 index.md と log.md の更新

書き戻した場合のみ:

- `index.md` の「トピック」カテゴリに `- [[topic-{slug}]] — {1 行サマリ}` を追加
- `log.md` に追記:

```markdown
## [{今日の日付}] query | {質問の要約}

- 回答先: topic-{slug}.md（書き戻し）または "(書き戻しなし)"
- 参照ページ: {読んだページのリスト}
- 矛盾検出: {あれば、なければ "なし"}
```

書き戻さなかった場合でも、**矛盾を検出していたら** log に記録する（lint で扱える形にしておく）:

```markdown
## [{今日の日付}] query | {質問の要約}

- 回答先: (書き戻しなし)
- 矛盾検出: [[page-a]] と [[page-b]] で {内容} が食い違う
```

矛盾も無く書き戻しもしない単純な質問では log を更新しない（log を雑に膨らませない）。

日付は必ず `date +%Y-%m-%d` で取得する（決め打ちしない）。

## 完了報告

最後にユーザーに伝える:

- 回答そのもの
- 参照したページ数
- 書き戻した場合は新規ページのパス
- 矛盾を検出した場合はその旨と「`wiki-lint` で精査できる」案内

## 禁止事項

- index.md を読まずに全ファイル走査する
- Wiki に無い内容を Wiki にあるかのように引用する
- 矛盾を勝手に解消する（並置・記録に留めて lint に委ねる）
- 単純な質問でも毎回書き戻す（書き戻しの基準を Phase 5 に従って厳密に判定する）
- 質問が曖昧なまま回答を進める（必要なら AskUserQuestion で絞る）
