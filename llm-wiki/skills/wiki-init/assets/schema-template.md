# LLM Wiki スキーマ

このファイルは LLM Wiki の **スキーマ**（運用規約）です。Wiki に対して何かを書き込む / 読み込む LLM は、まずこのファイルを読み、ここに書かれた規約に従って動作してください。

> 本ファイルは Claude Code が自動読込する `CLAUDE.md`、または汎用エージェント向けの `AGENTS.md` として配置されます。
>
> このスキーマは **育てるもの** です。運用していて気づいた規則・好みは末尾の「拡張」セクションに追記してください。
>
> **本スキーマは "不変条件" の規定** に専念し、操作の詳細手順は記載しません。詳細手順は `/llm-wiki:wiki-ingest` `/llm-wiki:wiki-query` `/llm-wiki:wiki-lint` `/llm-wiki:wiki-schema` の各スキルが担います。

## 三層構造

| レイヤー | 役割 | 編集権 |
|---|---|---|
| 生ソース | 元のドキュメント（記事・PDF・トランスクリプト等） | 不変。LLM は読むだけ |
| Wiki | 相互リンクされたマークダウンの集合体 | LLM が完全に所有して書き換える |
| スキーマ（このファイル） | Wiki の構造・ワークフローを定義 | 人間と LLM の合議で更新 |

新しい知識は **生ソース → Wiki への要約 → 関連ページの相互更新** の順で流れる。生ソースを毎回読み返すのではなく、Wiki に書き込んだ内容を一次情報源として参照する。

## ディレクトリ構成

```
{wiki-root}/
├── CLAUDE.md           # このスキーマ
├── index.md            # ページカタログ（必読）
├── log.md              # 追記専用の年代記
├── README.md           # （任意）人間向けの導入
└── *.md                # Wiki ページ本体（フラット配置）
```

- 既定はフラット配置。Wiki のページ数が増えてカテゴリ単位の整理が必要になったらサブディレクトリ化を検討する
- `attachments/` は画像や PDF を貼り付けるときに作成する

## ページの命名規約

すべて kebab-case の `.md` ファイル。プレフィックスでページタイプを示す。

| プレフィックス | 用途 | 例 |
|---|---|---|
| `source-` | 生ソースの要約ページ（1 ソースに 1 つ） | `source-attention-is-all-you-need.md` |
| `concept-` | 概念・用語ページ | `concept-self-attention.md` |
| `person-` | 著者・研究者・関係者 | `person-vaswani.md` |
| `topic-` | 横断的なテーマ・分野 | `topic-llm-architecture.md` |

> 用途に応じてここを増減させる。例: 個人運用なら `goal-` / `metric-`、プロジェクトなら `decision-` / `incident-`。

## ページのフロントマター

すべての Wiki ページは YAML フロントマターを持つ。

```yaml
---
title: ページの正式な題名
type: source | concept | person | topic     # 上記のページタイプに対応
created: YYYY-MM-DD
updated: YYYY-MM-DD
tags: [tag1, tag2]                          # 任意
aliases: [別称1, 別称2]                      # 任意。検索用の別名
source_url: https://...                     # type=source のときのみ必須
---
```

- `created` は最初に作成された日付。以後変更しない
- `updated` は実体的な更新があったときのみ更新する（typo 修正では更新しない）

## 相互リンク

Obsidian 互換の wikilink 記法 `[[ページのファイル名（拡張子なし）]]` を使用する。

```markdown
このアーキテクチャは [[concept-self-attention]] に基づいており、[[person-vaswani]] らによって提案された。
```

- リンク先のページが存在しない場合は **作成して空ページにしない**。代わりに ingest / query 実行時の log エントリ内に「作成候補: [[xxx]]」として記録するか、lint で「欠落概念」として扱う
- ページ末尾には常に「## 関連」セクションを置き、双方向リンクのアンカーにする

## index.md

Wiki に存在するすべてのページを **1 行サマリ付き** でカテゴリ別に列挙するカタログ。

- LLM はクエリを受けたら **まず index.md を読む**
- 1 行サマリは「このページは何を扱っているか」を 1 文で
- 新規ページを追加・実体的な内容変更を行ったら必ず index.md を更新する

形式例:

```markdown
## 概念
- [[concept-self-attention]] — 入力系列の各要素に対する重み付き集約の機構
- [[concept-positional-encoding]] — 位置情報を埋め込みに加える手法

## ソース要約
- [[source-attention-is-all-you-need]] — Transformer の原典論文（2017）
```

## log.md

追記専用の年代記。ingest / query / lint / schema 変更などのイベントを時系列で記録する。

エントリのプレフィックスは Unix ツールでパースできる形式に揃える:

```markdown
## [YYYY-MM-DD] {action} | {title}

- {要点1}
- {要点2}
```

`action` の値:

| action | 意味 |
|---|---|
| `init` | Wiki 初期化 |
| `ingest` | 新ソース取り込み |
| `query` | 価値あるクエリと回答（Wiki に還元したもの） |
| `lint` | 健全性チェックの結果 |
| `schema` | スキーマ変更 |
| `note` | その他特記事項 |

## ワークフロー（不変条件）

ingest / query / lint / schema 各操作は対応するスキル（`/llm-wiki:wiki-*`）が手順を持つ。本スキーマは **どの手順を踏んでも守るべき不変条件** だけを規定する。

### ingest（取り込み）の不変条件

- 1 つの生ソースに対して **必ず 1 つ** の `source-*.md` を作る（複数 source を 1 ファイルに混ぜない）
- 取り込み実行ごとに `index.md` と `log.md` を **必ず更新** する
- 既存ページの記述と矛盾するソースを取り込んだ場合、**既存記述を消さず並置** する

### query（問い合わせ）の不変条件

- 回答は Wiki 内のページから組み立てる。Wiki に無い情報を補った場合は **その旨を明示** する
- 主張の根拠は `[[source-*]]` まで遡れる形で引用する
- 価値ある回答（新しい横断的知見）は **必ず Wiki に書き戻す**（書き戻す/書き戻さないの判定基準はスキルが持つ）

### lint（健全性チェック）の不変条件

- **検出のみ行い、自動修正はしない**（ファイル削除・リンク削除・矛盾の片寄せを LLM 単独で実行しない）
- レポートと log エントリを残し、修正は人間 / 別スキル / 後続 ingest に委ねる

### schema（スキーマ変更）の不変条件

- 既存ページに影響する変更（命名規則変更等）は **マイグレーション計画を分離** してから実施する
- スキーマ変更は `log.md` に `schema` action で **必ず記録** する
