# Wiki 初期化

LLM Wiki の永続的なナレッジベースを新規に立ち上げる。スキーマ（CLAUDE.md）はテンプレートをそのままコピーするのではなく、用途に応じてセクションを取捨選択し、ユーザーの言葉でカスタマイズする。

## 基本原則

- **スキーマ（CLAUDE.md）は Wiki 運用の憲法**: ここに書かれた規約に従って ingest / query / lint が動く。曖昧なまま立ち上げると Wiki が散らかる
- **テンプレートは出発点**: 用途を聞き取ってから不要なセクションを削り、用途固有のページタイプを足す。「全部入りの巨大スキーマ」を渡さない
- **既存 Wiki を破壊しない**: ルートに `CLAUDE.md` または `index.md` が既にあれば、確認なしには絶対に上書きしない
- **永続性を意識**: 数か月〜数年使うことが前提。最初に決めた命名規則は後から変えにくいので、用途を踏まえて慎重に決める

## ワークフロー

```
入力（パス or 空）
  │
  ├─ Phase 1: Wiki ルートの確定と既存チェック
  ├─ Phase 2: 用途の聞き取り（インタビュー）
  ├─ Phase 3: スキーマ（CLAUDE.md）の生成
  ├─ Phase 4: index.md / log.md / README の生成
  ├─ Phase 5: 初期コミットの提案
  └─ Phase 6: 次のアクション案内
```

## Phase 1: Wiki ルートの確定と既存チェック

### 1.1 ルートパスの決定

`$ARGUMENTS` を以下のように扱う:

| 入力 | 扱い |
|---|---|
| 絶対パス・相対パス | そのパスを Wiki ルートとして採用 |
| 空 | デフォルト `./wiki/` を提示し AskUserQuestion で確認 |

提示する候補例:

```
Wiki ルートをどこにしますか？
1. ./wiki/         — このリポジトリ配下（推奨。既存プロジェクトと同居させる場合）
2. ./              — リポジトリのトップレベルを Wiki にする（Wiki 専用リポジトリの場合）
3. カスタムパスを入力
```

### 1.2 既存ファイルの検査

候補パスの直下を確認し、以下のいずれかが存在する場合は **絶対に上書きせず** 中止する。

- `CLAUDE.md` または `AGENTS.md`
- `index.md`
- `log.md`

中止時のメッセージ例:

```
{wiki-root} には既に Wiki らしきファイルがあります（CLAUDE.md / index.md など）。
- 既存スキーマを変更したい場合: /llm-wiki:wiki-schema を使ってください
- 別の場所に新規作成したい場合: 別のパスを指定してください
- それでも上書きしたい場合: 既存ファイルを退避またはコミットしてから再実行してください
```

ディレクトリ自体が存在しない場合は、ここで `mkdir -p <wiki-root>` を実行してから Phase 2 に進む（既存ファイル上書きの心配は無いので前倒しで作成して構わない）。

## Phase 2: 用途の聞き取り

`AskUserQuestion` で以下を最低限確認する。1 度の質問で複数の選択肢を提示してもよいが、全てを一度に詰め込まない。

### 2.1 主要用途（必須）

```
この Wiki の主な用途は？（複数選択可）
1. 研究・読書: 論文・記事・本のサマリと相互リンク
2. 個人: 目標・健康・自己改善の記録
3. プロジェクト: チーム内ドキュメント / 技術ナレッジ
4. 競合・市場分析
5. 学習・コース整理
6. その他（自由記述）
```

### 2.2 想定ソース種別（必須）

```
取り込む主なソースは？
- Web 記事 / ブログ
- 論文（PDF）
- 動画・ポッドキャストのトランスクリプト
- Slack / メール / 議事録
- 自分のメモ・日記
- 書籍・章単位の読書ノート
- その他
```

### 2.3 スキーマファイル名（任意）

```
スキーマファイル名は？
1. CLAUDE.md（推奨。Claude Code が自動で読み込む）
2. AGENTS.md（汎用エージェント向け）
3. 両方を作成（CLAUDE.md を AGENTS.md にもコピー）
```

### 2.4 ページタイプの追加質問（必要に応じて）

`schema-template.md` には以下 4 種のページタイプが標準で含まれる: `source-` / `concept-` / `person-` / `topic-`。

主要用途に応じて、この標準セットから不要なものを削るか、用途固有のページタイプを追加で提案する:

| 用途 | 標準から残すもの | 追加で提案するもの |
|---|---|---|
| 研究・読書 | 全部残す | （特になし） |
| 個人 | source- / topic- | `goal-`（目標）、`metric-`（指標） |
| プロジェクト | 全部残す | `decision-`（意思決定記録）、`incident-`（インシデント） |
| 競合分析 | source- / topic- | `company-`、`product-` |
| 学習 | source- / concept- / topic- | `question-`（自分の疑問） |

複数用途が選択された場合は、各行の和集合から提案する。**ただし種類が増えすぎる（5 種以上）と運用が煩雑になる**ことをユーザーに伝え、優先度を確認する。

## Phase 3: スキーマ（CLAUDE.md）の生成

`assets/schema-template.md` をベースに、Phase 2 の回答に従って以下を行う:

1. **冒頭の "目的" を 1〜2 文でユーザーの言葉で記述**: 「この Wiki は X のために運用する」を明示する
2. **ページタイプ表を Phase 2.4 の合意に揃える**:
   - 標準 4 種（`source-` / `concept-` / `person-` / `topic-`）のうち、Phase 2.4 で「残す」とした行のみ表に残す
   - Phase 2.4 で「追加で提案するもの」が合意されたら表に追加し、用途を 1 行で説明
3. **想定外のソース種別への言及を削減**: Phase 2.2 で挙がらなかったソース種別（例: 議事録だけ運用する Wiki なら論文 PDF への言及）に関する記述を削る
4. **言語**: テンプレートは日本語ベース。ユーザーが英語運用を希望すれば英語に置換する

スキーマの中で必ず残すべき骨子（削除してはいけない）:

- Wiki の三層構造（生ソース / Wiki / スキーマ）の説明
- `index.md` と `log.md` の役割と更新ルール
- 相互リンクの記法（`[[wiki-link]]`）
- ingest / query / lint の各ワークフローの位置づけ（**詳細手順はテンプレートに含めない。スキーマは "不変条件" の規定**）
- ページのフロントマター規約（最低限 `title` と `type`）

ユーザー固有の運用ルールがあれば末尾の「拡張」セクションに追記する。

## Phase 4: index.md / log.md / README の生成

### 4.1 index.md

`assets/index-template.md` をそのままコピーする。テンプレートは標準 4 カテゴリ（ソース要約 / 概念 / トピック / 人物）を含む。

Phase 2.4 で標準ページタイプから一部を削った場合 / 追加した場合は、コピー後に index.md のカテゴリ見出しもそれに揃える。**カテゴリ名はページプレフィックスと素直に対応**させる（例: `decision-` を追加したらカテゴリ「意思決定記録」を追加）。

### 4.2 log.md

`assets/log-template.md` をコピー。先頭にプレフィックス規約の説明を残す（`## [YYYY-MM-DD] {action} | {title}`）。

最初のエントリとして以下を追加:

```markdown
## [{今日の日付}] init | Wiki 初期化

- 用途: {Phase 2 で聞いた主用途}
- 想定ソース: {Phase 2.2 の回答}
```

日付は `date +%Y-%m-%d` で取得すること（決め打ちしない）。

### 4.3 README.md（任意）

以下を満たす場合のみ作成する:

- Wiki ルートが既存リポジトリ内のサブディレクトリ（つまりルートに親リポジトリの README が別途存在する）
- かつ `<wiki-root>/README.md` がまだ存在しない

満たすときは「この Wiki は何か / どう使うか」を 5〜10 行で書く。

ルート直下を Wiki にする場合 / 既存 README がある場合は新規作成しない。

## Phase 5: ファイル配置とコミットの提案

### 5.1 ファイル配置

Phase 3〜4 の生成物を `<wiki-root>` に配置する（ディレクトリは Phase 1.2 で作成済み）。配置後にツリーをユーザーに提示:

```
{wiki-root}/
├── CLAUDE.md
├── index.md
├── log.md
└── README.md   （任意）
```

### 5.2 git の扱い

判定: `git -C <wiki-root> rev-parse --is-inside-work-tree 2>/dev/null` を実行し、終了コード 0 かつ `true` が出力されれば既存 git リポジトリ内、それ以外なら外と判断する。

- **既存 git リポジトリ内** → ステージングのみ提案（`git add` の対象を提示してユーザーに委ねる）
- **外** → `git init` の実行可否をユーザーに確認

コミットそのものは実行しない。`/llm-wiki:wiki-init` が勝手に commit を作るのは越権。

## Phase 6: 次のアクション案内

最後に必ず以下を伝える:

```
Wiki を初期化しました: {wiki-root}

次のステップ:
- ソースを取り込む:   /llm-wiki:wiki-ingest {URL or path}
- 質問する:           /llm-wiki:wiki-query {質問}
- 健全性チェック:     /llm-wiki:wiki-lint
- スキーマをカスタマイズ: /llm-wiki:wiki-schema

スキーマ（{wiki-root}/CLAUDE.md）は最初の出発点です。
運用しながら気づいたルールを追記して育ててください。
3〜5 ソース取り込んだあたりから cross-reference の累積効果が出てきます。
```

## 禁止事項

- 既存の `CLAUDE.md` / `index.md` / `log.md` の上書き
- ユーザー確認なしの `git init` または `git commit`
- テンプレートのフルコピー（用途を聞かずに全部入りスキーマを置くのは避ける）
- 想定外のサブディレクトリの先回り作成（`pages/` `attachments/` 等は必要になってから足す）
