# hypothesis-investigator 設計ノート

> 定義=hypothesis-investigator.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。

## 役割と位置づけ

debug-investigate スキルのステップ5（並列検証）専用の検証者。全体のアーキテクチャ判断（仮説並列検証型・汎用1種にした理由）は `skills/debug-investigate/RATIONALE.md` を参照。

## 中核的な設計判断

### 【load-bearing】tools から Write / Edit を除外
- **決定**: 非破壊制約（作業ツリーを変更しない）をプロンプトの指示だけでなくツール権限でも構造的に保証する
- **防いでいる失敗**: 指示の読み飛ばしや「少しだけログを仕込む」逸脱による並列調査の汚染。Bash 経由の書き込みは残るため、プロンプト側の禁止列挙（ファイル編集・ログ仕込み・checkout/bisect・データ書き換え）と二段構えにしている
- **出所**: 設計議論（2026-07）

### supported 時の「反証の試み」必須
- **決定**: supported と判定する場合、何の反証を試みて仮説が生き残ったかの記載を必須にした
- **防いでいる失敗**: 支持証拠だけを集めた見かけ上の supported をメインが裁定で見抜けない（報告に反証過程がなければ検証不十分と判断できる）
- **出所**: 設計議論（2026-07）

### 「副次的手がかり」と「実験提案」フィールド
- **決定**: 担当仮説の判定と別に、調査中に見えた他の原因の可能性と、非破壊では検証しきれない実験の提案を返させる
- **防いでいる失敗**: 全仮説が refuted のラウンドで次の仮説の種が無くなる（副次的手がかりが再生成の入力になる）／非破壊制約が検証の行き止まりになる（実験提案でメインの逐次実験に引き継ぐ）
- **出所**: 設計議論（2026-07）
