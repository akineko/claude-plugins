# test-refactor-cross-analyzer 設計ノート

> 定義=test-refactor-cross-analyzer.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。全体設計は skills/test-refactor/RATIONALE.md 参照（特に「2段階検出」「cross-analyzer は1体」の判断・仮定）。

## 中核的な設計判断

### 【load-bearing】ソース裏取りなしの指摘禁止
- **決定**: インベントリ突合は候補出しにのみ使い、指摘には必ず両側のソース精読を要求。
- **防いでいる失敗**: 要約（lossy）同士の突合だけで「同じ振る舞い」と誤認し、それが削減的変換（テスト削除）の根拠に化けること。削減の誤指摘はこのスキルで最も重大な事故で、検証プロトコル（mutation check）まで到達する前にここで落とすのが最初の防衛線。

### 読み取り専用ツール構成
- **決定**: Read / Grep / Glob のみ。
- **防いでいる失敗**: 分析係が「ついでに」修正へ踏み出す逸脱。

### 【load-bearing】裏取りとスコープの区別（スコープ外は読んでよいが削減根拠にできない）
- **決定**: 手順に「裏取りとスコープの区別」を明記し、スコープ外根拠の指摘は要ユーザー判断化。禁止事項にも追加。
- **防いでいる失敗**: iteration-1 の eval scoped-monorepo で実証 — 裏取り指示が「読んだスコープ外テストを削減根拠に転用する」挙動を誘発し、スコープ境界を越えた削減（このスキル最大の事故類型）が発生した。裏取り指示自体は誤検出防止に必要なので削れず、区別の明文化で対処。
- **出所**: eval scoped-monorepo iteration-1（2026-07）
