# test-refactor-surveyor 設計ノート

> 定義=test-refactor-surveyor.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。全体設計は skills/test-refactor/RATIONALE.md 参照（特に「2段階検出」判断）。

## 中核的な設計判断

### 【load-bearing】インベントリはファイル出力・指摘はインライン
- **決定**: 大きい成果物（検証インベントリ）は Write でファイルへ、小さい成果物（指摘）は最終メッセージで返す。Write を持つのはこのため（用途は出力先ディレクトリ限定）。
- **防いでいる失敗**: インベントリをインライン返却すると、並列 surveyor の数 × インベントリでメインコンテキストが圧迫されること。

### 【load-bearing】テスト実行禁止
- **決定**: Bash は持つがテスト実行を禁止事項に明記。
- **防いでいる失敗**: 並列起動された surveyor が一斉にテストを回して資源競合し、かつ自身のコンテキストをログで潰す事故。実行で得る情報（green/red・実行時間）は baseline-runner が供給済みで、重複取得になる。

### verifies の正規化を品質要件として明記
- **決定**: テスト名の写しではなく、実装を読んで正規化した一文を要求。
- **防いでいる失敗**: cross-analyzer の突合が名前の表記揺れで空振りし、横断分類（このスキルの主要な検出対象）が全滅すること。横断分析の上限はこの欄の品質で決まる。
