# refactor-scan-architecture 設計ノート

> 定義=refactor-scan-architecture.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。

## 役割と位置づけ

refactor-scout の3レンズ分割の一角（主役レンズ）。レンズ分割・二軸分離（影響度のみ付与）・レーン規律の「なぜ」は `skills/refactor-scout/RATIONALE.md` 参照。

## 中核的な設計判断

### 【load-bearing】大規模スキャンでも分割しない唯一のレンズ
- **決定**: スコープをシャード分割する規模でも、architecture だけは全域を1エージェントで見る。
- **防いでいる失敗**: 循環依存・レイヤ違反はシャードを跨いで初めて見える。分割すると主役レンズの検出対象が原理的に消える。依存把握は grep（import/require）中心で全ファイル本文を読む必要がないため、全域でもコンテキストが持つという見立て。
- **出所**: プラグイン拡張時の設計判断（2026-07）。⚠️ 巨大リポジトリでこの見立てが破れる場合は、モジュール境界レベルの粗い依存図に落とす等の再設計が要る。

### 「綺麗な理想形」を押し付けない（実害基準）
- **防いでいる失敗**: 健全なモジュールの候補化（捏造）。eval `whole-repo-prioritized` のデコイ assertion で検証済み。
