# test-refactor-baseline-runner 設計ノート

> 定義=test-refactor-baseline-runner.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。全体設計は skills/test-refactor/RATIONALE.md 参照（特に「生ログ非搭載」判断 — 本エージェントの存在理由そのもの）。

## 中核的な設計判断

### 【load-bearing】watch モード回避の明文化
- **決定**: `CI=true` 付与と vitest の `--run` 明示を手順に含める。
- **防いでいる失敗**: jest/vitest の watch 起動によるハング（サブエージェントがタイムアウトまで戻らず、Phase 0 全体が停止する）。

### 生ログのファイルリダイレクト
- **決定**: 実行ログはファイルへ落とし、grep で必要箇所だけ抽出する。
- **防いでいる失敗**: メインだけでなく本エージェント自身のコンテキストもログで溢れ、返却サマリの品質が落ちること。

### ファイル別実行時間はベストエフォート
- **決定**: JSON レポーターで取れなければ粗い粒度＋warnings 申告で返す。
- **却下した代替案**: 時間計測の必須化 — フレームワーク差異で達成不能なケースがあり、Phase 5 の前後比較は implementer が同条件で測り直すため必須ではない。

### 編集ツールを持たせない
- **決定**: tools から Write / Edit を除外。
- **防いでいる失敗**: red なテストを「親切に」直してしまう逸脱（red はそのまま報告するのが仕事）。
