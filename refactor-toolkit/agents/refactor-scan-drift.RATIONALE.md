# refactor-scan-drift 設計ノート

> 定義=refactor-scan-drift.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。

## 役割と位置づけ

refactor-scout の3レンズ分割の一角（文書化意図・支配的パターンからの乖離担当）。レンズ分割・二軸分離・レーン規律の「なぜ」は `skills/refactor-scout/RATIONALE.md` 参照。

## 中核的な設計判断

### 【load-bearing】基準の先固定（基準なしに乖離を探さない）
- **決定**: 文書化意図・支配的パターンという基準を確定してから外れを探す手順を固定。
- **防いでいる失敗**: 基準なしの「一般論として綺麗か」評価は architecture / locality と重複し、レンズ分離が崩れる。drift の存在意義は基準照合の専門化にある。

### 「意図に沿う箇所」の逆方向の申し送り
- **決定**: 意図に沿っているのに一見スメルに見える箇所を、候補ではなく申し送りとして報告させる。
- **防いでいる失敗**: オーケストレータが他レンズ由来の同箇所候補を誤って採用する事故（凍結ファイル・ADR 明示例外の候補化）。eval `adr-money-frozen` の棄却 assertion で検証済み。
