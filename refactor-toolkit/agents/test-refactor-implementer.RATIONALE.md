# test-refactor-implementer 設計ノート

> 定義=test-refactor-implementer.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。全体設計は skills/test-refactor/RATIONALE.md 参照（特に「検証プロトコル」「git checkout 不使用」「逐次実行」の判断）。

## 中核的な設計判断

### 【load-bearing】適用前の再検証
- **決定**: 各項目の適用前に現状コードで前提を確認し、崩れていれば skipped。
- **防いでいる失敗**: `--apply` での後日再開や先行グループの変更で計画が古くなっているのに、機械的に適用して壊すこと。

### 【load-bearing】失敗時のバックアップ復元
- **決定**: 着手前コピーを保存し、検証が通らなければ書き戻して failed 報告。
- **防いでいる失敗**: 「変換済みだが未証明」という最悪の中間状態が作業ツリーに残ること（green に見えて検証力が落ちている可能性があり、後から検出できない）。

### 検証プロトコルの省略禁止（省略するくらいなら skipped）
- **決定**: 時間が掛かる場合も check を省略・弱い方法へ差し替えない。
- **防いでいる失敗**: 適用件数を稼ぐために証明が形骸化し、スキルの不変条件1（検証力を弱めない）が実質無効になること。

### スコープ外マッピング項目の適用拒否と期待値リテラル固定
- **決定**: 計画にスコープ外根拠の削減項目が紛れ込んでいても適用せず skipped。期待値をプロダクション関数で計算する書き換えを禁止。
- **防いでいる失敗**: 上流（cross-analyzer・計画）のチェックをすり抜けた場合の最終防衛線。iteration-1 の eval scoped-monorepo で両方の事故が実際に発生した。
- **出所**: eval scoped-monorepo iteration-1（2026-07）
