# checkpoint — 途中の再同期

会話が長くなると、ユーザーと AI の頭の中は静かに乖離する（決めたつもり／聞いたつもり／終わったつもり）。現在地を1画面で照合し、ズレをその場で修正できるようにする。

## 手順 1: 情報源の収集

1. **この会話** — 依頼・決定・方針転換・保留にした話題を遡って拾う
2. **合意**（あれば） — 合意ファイル（`docs/agreements/` の active なもの）またはインライン合意
3. **作業ツリー** — `git status` / `git diff --stat` で実際の変更を確認（記憶ではなく現物で）

## 手順 2: 1画面レポート

以下の構成で提示する。**全体で1画面（目安 25 行以内）**。詳細に立ち入らず、ズレの発見に必要な粒度だけ:

1. **目標** — いま何のために作業しているか（合意の要点、1〜2行）
2. **確定した決定** — この会話でユーザーと合意した選択（番号付き。「決めたつもり」の照合点）
3. **進捗** — 完了条件（なければタスク）ごとに: 完了 ✅ / 作業中 🔧 / 未着手 ⬜
4. **未報告の裁量判断** — 決定台帳の確認列が空欄のもの、またはまだ話していない判断（なければ「なし」）
5. **合意とのズレ** — 実際の変更ファイルと合意スコープの食い違い、宣言した前提で崩れたもの（なければ「なし」）
6. **次の一手と保留** — 次にやること1つ＋ユーザーの回答待ち・保留中の話題

## 手順 3: ズレの修正

レポートに対するユーザーの指摘（「それは決めてない」「その判断は違う」等）があれば、その場で合意・作業方針に反映する（合意ファイルがあれば決定台帳に記録）。指摘がなければそのまま作業に戻る。

## 規律

- レポート生成でファイルを更新しない（checkpoint は何度呼ばれても安全な読み取り専用。唯一の例外は手順 3 でのユーザー指摘の記録で、それ以外の永続化は handoff の役割）。
- 記憶で書かない。進捗と変更は `git status` 等の現物で裏取りしてから書く。
- 「未報告の裁量判断」と「合意とのズレ」は該当なしでも項目を省略せず「なし」と明記する（書いてないのか無いのかをユーザーに推測させない）。
- 良く見せない。遅れている・詰まっている・想定と違ったは、そのまま書く。
