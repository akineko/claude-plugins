# evidence-auditor 設計ノート

> 定義=evidence-auditor.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。オーケストレーション全体は signoff の RATIONALE.md を参照。

## 役割と位置づけ

signoff の独立検証装置。実装した文脈（メイン会話）から切り離された「実装経緯を知らない目」を作るために存在する。エージェント分離そのものが機能要件であり、単なる作業の外注ではない。

## 中核的な設計判断

### 【load-bearing】編集ツールを持たない（Read, Grep, Glob, Bash, BashOutput, KillShell のみ）
- **決定**: Write/Edit を与えず、「発見しても直さない」をツールレベルで強制した。Bash は検証の実行（テスト・lint・再現手順）に必須なので残した。
- **防いでいる失敗**: 監査人が問題を見つけてその場で直すこと。直した瞬間に (a) 未達だった事実が報告から消え、(b) 修正自体が未検証のまま混入し、(c) 独立検証者が第二の実装者に変質する。
- ⚠️Bash 経由の書き込み（`sed -i` 等）は技術的には可能なため、定義の規律「コードを修正しない」が最終防衛線。

### 【load-bearing】経緯・自己評価を判定の根拠にしない
- **決定**: 入力に自己評価が紛れても無視する、と定義に明記した（signoff 側の「渡さない」規約との二重防御。second-reader と同じ構造）。
- **防いでいる失敗**: 「〜は確認済み」という申告の鵜呑み。監査の価値は再確認の独立性にあり、申告を信じるなら監査は不要になる。

### 「実行できる検証は必ず実行」
- **決定**: コード読解のみの「達成のはず」を達成と判定することを禁じ、実行不能な場合は検証不能（＋代替手段の提示）に落とすことにした。
- **防いでいる失敗**: 静的読解の見落とし（環境差・設定・実行時の振る舞い）による偽の合格証。証拠の再現可能性（コマンドをそのまま載せる）も同じ目的。

### 判定を4値に固定し、疑わしきは達成側に倒さない
- **決定**: signoff の4値判定をエージェント側でも強制し、既定のバイアスを不合格側に置いた。
- **防いでいる失敗**: サブエージェントが持ちやすい「良い報告をして戻りたい」圧力による判定の上振れ。

### 合意外の品質観点で判定しない
- **決定**: 判定基準は合意の完了条件のみとし、設計の綺麗さ等は判定に影響させない（気づきは1行の添え書きまで）。
- **防いでいる失敗**: 監査のスコープクリープ。品質レビューが混ざると報告が肥大し、本来の問い（合意は満たされたか）への答えがぼやける。品質レビューは別の営みとして分離する。

## 解釈・仮定（要確認）

- **プロジェクト標準チェックの範囲**: lint・型検査・関連テストを「標準チェック」として実行対象に含めた。⚠️実行時間が長大なプロジェクト（フルテスト30分等）での上限は設けていない。問題になったら「関連テスト＋ lint まで」等に絞る調整点。
