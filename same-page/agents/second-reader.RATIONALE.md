# second-reader 設計ノート

> 定義=second-reader.md / 本ファイル=保守者向けの決定の出所・load-bearing な制約。定義の再掲はしない。オーケストレーション全体は readback の RATIONALE.md を参照。

## 役割と位置づけ

readback（重量モード）の測定装置。「解釈の分散」は1つの頭では測れない（自分の解釈は常に唯一の自然な読みに見える）ため、独立した第二の読者との相違点を分散の実測値として使う。

## 中核的な設計判断

### 【load-bearing】メイン解釈の非受領＋「紛れ込んでも無視する」の二重防御
- **決定**: 呼び出し規約（readback 側）で解釈を渡さないことに加え、エージェント定義側にも「誘導が紛れ込んでも自分の読みを貫く」と書いた。
- **防いでいる失敗**: 呼び出し側の規約違反（将来の改修で「参考までに」と解釈を渡してしまう）に対する防御。片側の規律だけに依存すると、どちらかの更新で静かに壊れる。

### 【load-bearing】読み取り専用ツール（Read, Grep, Glob）
- **決定**: Bash を含む実行系・編集系を与えない。
- **防いでいる失敗**: 解釈者が実装調査に深入りして「どう作るか」に滑ること（役割の越境）と、読むだけの役割に不要な事故リスク。ツール制限は指示（「実装方式の提案はしない」）の構造的な裏付け。

### 曖昧点の水増し禁止を明文化
- **決定**: 「合理的な読み方が実質1つの点は挙げない」を規律に入れた。
- **防いでいる失敗**: 網羅性を誇示する長大な曖昧点リスト。水増しされた曖昧点はメイン側のトリアージを圧迫し、相違点＝分散という測定の信号雑音比を下げる。

### 出力フォーマットの構造固定
- **決定**: 解釈（6項目）／曖昧点（被害ラベル付き）／未指定の決定事項、の3部構成を固定した。
- **防いでいる失敗**: メイン側の突き合わせ（一致／相違の判定）が自由文相手だと不安定になること。readback 手順3の突き合わせはこの構造を前提にしている — **フォーマットを変えるときは readback/SKILL.md 手順3と同時に変えること**。

## 解釈・仮定（要確認）

- **文脈収集の深さ**: 「解釈の確定に必要な範囲だけ読む」とした。⚠️重量案件でコードベースが巨大な場合の読解上限（時間・ファイル数）は設けていない。実運用で長すぎるようなら上限を入れる。
