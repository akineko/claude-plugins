# prompt-brief 設計ノート

> SKILL.md=「何をするか（指示）」/ 本ファイル=「なぜこの形か（意図・解釈・却下案・守る失敗）」。実行時は非読込。更新時に改訂する。SKILL.md は再掲せず参照に留める。

## 目的と背景

ユーザーの悩み（2026-07 の設計議論より）: 分岐の多いタスクをAIに依頼するとき、思いついたフローを伝えるとアンカリングで別アプローチを見逃し、目的だけ伝えると重要な考慮点が抜ける。このジレンマへの解として議論で確定した指針1（手順→失敗モード翻訳）・指針2（分岐→判断基準）をスキル化した。指針3（後出し比較プロトコル）はユーザーが明示的にスコープ外とした。

## 中核的な設計判断

### 【load-bearing】情報の「削除」ではなく「変換」として設計
- **決定**: 手順・分岐を単に削らせるのではなく、失敗モード・判断基準への翻訳を中核工程（§4）に置いた
- **却下した代替案**: 「フロー・手順を書かない」という禁止ルール型 → 手順に埋まっていた暗黙の要求ごと消え、元の悩みの片側（要件漏れ）がそのまま再発する
- **防いでいる失敗**: アンカリング回避と要件漏れ防止の両立が崩れること。このスキルの存在理由そのもの
- **出所**: 設計議論（2026-07）

### 【load-bearing】翻訳対応表の提示（Step 3）
- **決定**: ブリーフ完成形を出す前に「ユーザーの案 → 翻訳結果 → 行き先」の対応表を見せる工程を必須にした
- **防いでいる失敗**: 誤訳の不可視化。ハード制約が「防ぎたい失敗」に弱められたり、暗黙の要求ごと落とされたりしても、完成形だけ見せられたユーザーには何が削られたか分からない
- **出所**: 設計議論（2026-07）

### 【load-bearing】リトマス試験の例外: 外部制約由来の手順は残す
- **決定**: 「手順に見えても理由が外部要因（ライセンス・規約・互換性）なら導出不能情報としてハード制約に残す」を §2 と §4.1 の両方に明記
- **防いでいる失敗**: 機械的な「手順だから削除」で必須要件が消えること。翻訳質問（§4.1）の回答の行き先が3種（失敗/制約/落とす）に分かれているのはこのため
- **出所**: 設計議論（2026-07）

### 参考セクションは「翻訳しきれなかった案そのもの」1点のみ・ラベル必須
- **決定**: 「参考: 私が考えていた案（アンカーにしないこと）」の固定ラベル＋「縛られず提案してほしい」の添え書きを必須とし、乱用を落とし穴（§6）で禁止
- **却下した代替案**: 想定案を常に全文添付 → アンカリング再発。完全排除 → ユーザーが案を捨てきれず不安が残り、スキルが信頼されない
- **出所**: 設計議論（2026-07）

### 【load-bearing】不足情報の扱いを「背骨か枝葉か」で分岐・質問は選択肢付き
- **決定**: 背骨（判断基準・優先順位・分岐の理由・目的）の欠落は選択肢付き質問で埋め、枝葉（形式・環境・スコープ）は ⚠️仮定 を置いて草案へ進む（Step 2・§4.2・§6）
- **却下した代替案**: (A) 常に草案を先に出す → 背骨を推測で埋めると全体がその上に建ち、外れたとき骨格ごと崩れる。さらに確信ありげな仮定が今度はユーザーをアンカリングし、本スキルが防ぐ失敗が向きを変えて再発する。(B) 常に開いた質問 → 想起負荷が高く曖昧回答と尋問感を招く。選択肢付きは認識で答えられ、ユーザーが気づかない解釈を並置でき（抜け漏れ対策）、単一推測をぶつけないためアンカーにならない
- **防いでいる失敗**: 背骨の当て推量によるブリーフ全体の破綻とユーザー側アンカリング。および尋問化・一括実行での停止
- **出所**: iteration-1 eval2（分岐案＋失敗経験ありの入力）でスキルが開いた質問4問に倒れた挙動へのユーザー判断（2026-07）。「草案 vs 選択肢付き質問」の検討を経て背骨/枝葉の使い分けに確定

### インタビューは最大2ラウンド・既知情報は聞かない
- **決定**: Step 1 で会話から素材を拾い、Step 2 は不足した背骨のみ一括質問。既に明示された制約・失敗（例: 本番DB書き込み事故）は確定扱いで質問しない
- **防いでいる失敗**: 尋問化によるユーザーの疲弊（スキルが使われなくなる）。一括実行（eval・非対話文脈）で質問待ちのまま停止すること

## 解釈・仮定（要確認）

- **スコープ**: 「スキル設計依頼に特化 vs AIへの依頼全般」をユーザーに確認し、依頼全般を選択（2026-07）。スキル設計依頼は本文の例の一つとして扱う
- **「進め方への期待」セクション**: 指針3（後出し比較）はスコープ外だが、受け手AIに複数案提示を求める一文は依頼文の一部（協働の仕方の指定）と解釈してテンプレートの例に含めた。⚠️指針3の混入と見なすなら例文を差し替え可
- **起動方式**: 自動起動をユーザーが選択（2026-07）。prompt-engineer との境界は「永続的な指示文書ファイル vs 一回性の依頼文」と解釈し、双方の description に明記する運用とした
