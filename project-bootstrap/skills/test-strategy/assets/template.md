## 4. カバレッジ方針

### 4.1 計測対象と目標値

- **計測対象**: [行カバレッジ / 分岐カバレッジ / 該当なし]
- **目標値**: [数値目標を設けない（必須領域で代替） / 80% 以上 / 等]
- **しきい値の運用**: [CI でブロック / 警告のみ / 計測のみ]

> PoC・小中規模では数値目標を設けず、4.2 の必須領域の言語化を優先することを推奨。受託で契約要件があれば数値設定。

### 4.2 必ずテストすべき領域

- **クリティカルパス**: 概要書「2.2 主要ユースケース」の主要なフロー
- **認可ロジック**: セキュリティ書「3. 認可」のロール × リソース × アクションの権限判定
- **複雑なビジネスロジック**: [計算 / 状態遷移 / 検証ルール 等の具体例]
- **データ整合性**: [トランザクション境界 / 一意性制約 等が絡む処理]
- **その他**: [プロジェクト固有で必須の領域]

### 4.3 テスト不要・除外領域

- 自動生成コード（OpenAPI 生成のクライアント、Prisma 生成の型 等）
- フレームワーク提供のロジック
